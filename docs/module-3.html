Module 3 — Equip + Narrow Scope

An agent with a clear goal still needs the right context and a tight boundary.

1. Equip the agent

Give it only what it needs to do the job well:

  • Context — past examples, style guides, process notes
  • Tools — only the connections it actually requires
  • Playbooks — short step-by-step instructions for each sub-task

Best practice: when possible, let Grok learn from real past work instead of writing long manuals yourself.

Study these examples of how I usually do this work.
Write a short playbook that captures the pattern.
Use Plan Mode.

2. Narrow the scope (critical)

One agent should have one job. Broad agents get confused and make mistakes.

Bad: “Handle my inbox, calendar, and client follow-ups.”

Good: “Inbox only — sort, draft replies, and flag items that need me.”

If a job touches multiple areas, split it into separate specialist agents and (only if needed) add a Manager agent whose only job is coordination.

Manager agent prompt (use only when you have multiple specialists)
You are my Manager agent. You never do any task yourself.
When a job comes in, spin up or assign a dedicated sub-agent for that one job.
One agent, one lane. Coordinate and report back to me.
Use Plan Mode.

3. Best practices for Grok Build

  • Keep each agent in its own folder when practical.
  • Put lasting rules in an AGENTS.md file in that folder so Grok always sees them.
  • Prefer small, testable steps over one giant request.
  • After something works well, run /skillify to turn it into a reusable skill.

4. Practice lab (required)

Take the agent you started in Module 2 and:

  1. Write or generate one short playbook for its main sub-task.
  2. Add a clear boundary sentence to the IDENTITY file (“This agent only does X. It never does Y.”).
  3. Create a simple AGENTS.md in the folder with the six team safety rules plus the agent’s one-lane rule.
  4. Do all of the above with Plan Mode.
Done when

Your agent has a written playbook, an explicit boundary, and an AGENTS.md file.

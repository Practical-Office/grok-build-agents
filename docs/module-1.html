Module 1 — Safety Rules + Plan Mode

This is the most important module. Everything else depends on it.

Non-negotiable rule

For any non-trivial work, always tell Grok to use Plan Mode. Do not let it change files until you have read and approved the plan.

1. Why safety comes first

Grok Build can read files, edit files, and run commands on your computer. That is powerful. It is also dangerous if you skip approval.

Your job is not to make Grok faster. Your job is to stay in control while it does useful work.

2. The six team rules

#Rule
1Always start non-trivial work in Plan Mode.
2Never approve a plan you do not understand.
3One agent = one clear job (narrow scope).
4Do not give access to money, client data, or external systems until the agent has proven reliable on safer tasks.
5If you are unsure, stop and ask. Do not let the agent guess.
6Capture good results with /skillify so the team can reuse them.

3. How to force Plan Mode every time

When you start a task, end your request with this sentence:

Use Plan Mode. Do not make any changes until I approve the plan.

You can also type /plan inside Grok before or during a task.

4. How to review a plan

Before you approve, ask yourself:

  • Do I understand every step?
  • Is the scope limited to what I asked for?
  • Could this touch files or systems I do not want touched?
  • Is there a safer way to do the same thing?

If the answer to any of those is “I’m not sure,” do not approve. Rewrite the request or ask for a simpler plan.

5. Practice lab (required)

Open a new empty folder, start Grok, and run this exact request:

Create a short checklist called daily-habits.md with 5 simple habits for using Grok Build safely.
Use Plan Mode. Do not make any changes until I approve the plan.

Then:

  1. Read the full plan.
  2. Approve only if it is clear and limited.
  3. Open the file and confirm it looks right.
Done when

You can explain Plan Mode in one sentence and you have completed the lab above with a plan you personally approved.

Safety Rules + Plan Mode

This is the most important module. Everything else depends on it. All work happens inside the Grok Build CLI.

Non-negotiable rule

For any non-trivial work, always tell Grok to use Plan Mode. Do not let it change files until you have read and approved the plan.

Where you work

  1. Open a terminal.
  2. Go to your practice folder:
cd ~/grok-practice
  1. Start Grok:
grok

All prompts below are pasted inside the Grok Build CLI.

Why safety comes first

Grok Build can read files, edit files, and run commands on your computer. That is powerful — and dangerous if you skip approval. Your job is to stay in control.

The six team rules

#Rule
1Always start non-trivial work in Plan Mode.
2Never approve a plan you do not understand.
3One agent = one clear job (narrow scope).
4Do not give access to money, client data, or external systems until proven reliable.
5If unsure, stop and ask. Do not let the agent guess.
6Capture good results with /skillify.

How to force Plan Mode every time

Paste this sentence at the end of every real request (inside Grok Build CLI):

Use Plan Mode. Do not make any changes until I approve the plan.

Or type this alone:

/plan

How to review a plan — example

Imagine Grok shows a plan that says:

  1. Create daily-habits.md
  2. Write 5 safety habits
  3. Also update your calendar and email settings

Reject that plan. Step 3 is out of scope. Ask Grok to remove it, or paste:

Revise the plan. Only create daily-habits.md with 5 habits. Do not touch calendar, email, or any other files.
Use Plan Mode. Do not make any changes until I approve the plan.

Practice lab (required) — paste into Grok Build CLI
